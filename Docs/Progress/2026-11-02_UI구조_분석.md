# 2026-11-02 UI 구조 분석 (Asteria 0.3.5, 브랜치 `fix/critical-bugs-0.3.6`)

- 범위: 정적 코드 읽기만 수행. 빌드·실행·스크린샷 확인은 하지 않음. 코드 수정 없음.
- 근거는 파일:줄 형식. "미확인"은 코드만 보고 판단한 것이라 실행 확인이 필요함.

## 1. 한눈에 보는 구조

UI는 **즉시 모드(immediate mode)**다. 프레임마다 `main()`이 `GameState`를 보고 `Scene_*(SceneCtx)`를 호출하고, 각 함수가 입력·상태·그리기를 한 번에 처리한다. 위젯 트리나 보존되는 UI 객체는 없다.

```
main() 프레임 루프 (main.cpp)
 ├─ 게임 월드 그리기
 ├─ [outgame 장면]  main.cpp:6460 switch(state)
 │    MAIN_MENU ─┬─ (플래그) Shop / Codex / Settings / RunConfig 패널
 │    CODEX, TUTORIAL, CREATIVE_CONFIG, SETTINGS, READY, GAMEOVER,
 │    AUG_SELECT, DEBUFF_SELECT, AUG_REPLACE
 ├─ [인게임 HUD]   main.cpp:6540-6660  (RUNNING/PAUSED/DYING/AUG_*)
 │    VitalsHud(HP 호·XP 선) · WaveHud · SkillHud · 데미지 숫자 · 콤보 · FPS
 ├─ 버전 라벨 → 창 괄호(PaneBrackets) → PAUSED 장면(6685) → 디버그 툴킷 → 조준선
 └─ BatchFlush → SwapBuffers
```

| 계층 | 위치 | 역할 |
|---|---|---|
| 상태 | `Core/GameManager.h` | `GameState` 열거형 13개 + 런/UI 값 |
| 장면 | `Core/Scenes/*` | `Scene_*` 함수. `SceneMenus.cpp`가 `.inl` 4개를 `#include`해 약 5,000줄짜리 단일 번역 단위 |
| 공용 위젯 | `Scenes/SceneUI.*` | 버튼, 확인 대화상자, 뒤로 버튼, 텍스트 그림자, 텍스트 단계 |
| 레이아웃 | `Render/UiLayout.h` | `UiScale`, 하단 여백, 이징 |
| 색·깊이 | `Render/UiColors.h` | `DARK/LIGHT_THEME`, `UiDepth`, `UiContrast` |
| 그리기 | `Render/DrawPrim.h`, `TextRenderer.h` | CPU 배치, 글리프 아틀라스(폰트 4개 폴백), 폰트 3종(L/S/XL) |
| HUD | `Render/*Hud.h`, `*HudModel.h` | Model(GL 없음, 테스트됨) / View 분리 |
| OS 창 | `System/OsPane.*`, `PaneContent.h` | NORMA 보스용 실제 Win32 창 (UI라기보다 게임플레이) |

## 2. 화면 흐름

- **로비(MAIN_MENU)가 허브**다. 6개 경로: TUTORIAL, PLAY, SHOP, ASTRAL LOG, SETTINGS, EXIT (`SceneInternal.h:17-24`).
- PLAY·SHOP·CODEX·SETTINGS는 `GameState`가 아니라 **`s_MainMenu*Panel` bool 플래그**로 열리는 "인라인 패널"이다. `Scene_MainMenu`가 배경을 그린 뒤 플래그를 if 체인으로 검사해 해당 패널을 호출한다 (`SceneMainMenu.inl:24-42`). 패널은 서로 배타적이고 스택은 없다.
- 그럼에도 `GameState::CODEX / SETTINGS / CREATIVE_CONFIG`가 남아 있다. SETTINGS는 일시정지에서 열 때 실제로 쓰인다 (`g_SettingsReturnTo`). CODEX는 `Scene_Codex`(.inl 822줄)와 `Scene_CodexInline`(.inl 1,257줄)이 둘 다 있어 어느 쪽이 실사용인지 **미확인** — 중복이면 약 2천 줄 정리 후보.
- 튜토리얼 READY 화면 안의 증강 카드는 `glViewport`+`glScissor`+`g_ViewportMap`으로 화면을 축소해 끼워 넣는다 (`main.cpp:6477-6507`). 동작은 하지만 입력 좌표 변환을 손으로 해야 하는 우회책이다.
- 일시정지는 HUD 뒤에 그려서 베일이 HUD까지 덮도록 순서가 의도적으로 뒤로 밀려 있다 (`main.cpp:6509`, `6685`).

## 3. 공용 위젯 (SceneUI)

- 텍스트 단계 4개 (`UiTextLevel`): 기준 46px × {1.0, 0.82, 0.56, 0.42} × 반응형 스케일 (`SceneUI.cpp:105`). 일관된 좋은 설계.
- 버튼이 **세 가지**: `UIButton`(구형, 중앙 정렬·클릭 시 *뗄 때*), `DrawPanelButton`, `DrawUnifiedMenuCommand`(왼쪽 정렬 명령 줄·*누를 때*). 뒷 두 개는 시그니처가 거의 같고 `bothSides`/`slideSide`만 다르다.
- `UIButton`의 호버 애니메이션 상태는 **위치·크기(±0.25px)를 키로 한 128칸 정적 배열**에 저장된다 (`SceneUI.cpp:32`). 버튼 위치가 움직이면 매 프레임 새 슬롯을 먹거나 호버가 끊긴다.
- `DrawConfirmDialog`는 정적 변수 `s_openT`, `s_hover[2]` 하나를 모든 호출자가 공유한다 (`SceneUI.cpp:440`대). 한 프레임에 두 대화상자가 열릴 일은 없지만, 닫을 때 `open=false`로 한 번 더 호출해 리셋해야 하는 규약이 호출처마다 반복된다 (`SceneMainMenu.inl:270-280`, `ScenePause.cpp:245-256`).
- `DrawBottomLeftBackButton`은 공통화됐지만 크기(286×64)는 `SceneRunConfig.cpp`·`SceneSettings.cpp`에도 복제돼 있다고 기존 문서(PP-08)가 기록함.

## 4. 레이아웃 · 테마

- 기준 해상도 1640×910, `UiScale = clamp(min(sw·0.94/1640, sh·0.90/910), 0.70, 1.35)` (`UiLayout.h:6`). 사용처 25곳.
- 일부 장면은 `uiScale`을 곱하지 않은 값을 섞어 쓴다. 예: 일시정지 `btnX0 = max(58.0f, sw*0.075f)` (`ScenePause.cpp:128`) ↔ 로비 `max(58.0f*uiScale, sw*0.075f)` (`SceneMainMenu.inl:114`). 작은/큰 창에서 두 화면의 왼쪽 기준선이 어긋날 수 있음 (**미확인**, 해상도별 캡처 필요).
- **테마 시스템이 사실상 미사용**: `UiColors.h`에 DARK/LIGHT 팔레트, `UiDepth`, `UiContrast`가 정의돼 있으나 `GetUiTheme()` 호출은 6곳, `UiDepth::`/`UiContrast::`/`UiCol::`의 `Scenes/` 안 사용은 **0곳**, `SetUiTheme()`를 부르는 곳도 없다. 대신 `0.48f, 0.82f, 1.0f`, `0.18f, 0.62f, 0.96f`, `0.34f, 0.72f, 1.0f` 같은 청색 리터럴이 장면마다 반복된다 (리터럴 색 호출 최소 29줄, grep 기준). LIGHT 테마는 설정에 노출된 적이 없다.

## 5. 입력 · 내비게이션

- **ESC/뒤로가기가 두 층**에서 처리된다: (a) `GameManager::HandleInput` → `TryEscNavigateBack()` (`GameManager.cpp:142`, `SceneMenus.cpp:1391`)이 상태 단위로, (b) 각 패널이 자체 `prevEsc` 정적 변수로 에지를 직접 검출 (Codex·Shop·RunConfig·Settings 각각, `ScenePause.cpp`는 `s_InventoryEscArmed`). 에지 검출 코드가 5곳에 복제돼 있고, 포커스 복귀 처리(`inputFocusChanged`)를 빠뜨리면 버그가 된다.
- 현재 작업 트리에서 `TryEscNavigateBack`의 SETTINGS 분기는 저장을 하지 않도록 바뀌어 있다 (`SceneMenus.cpp:1420-1424`). 기존 분석서의 "ESC 시 무조건 저장" 항목이 이 브랜치에서 수정 중인 것으로 보임.
- 일시정지 인벤토리(`showOwnedAugments`) 중 ESC: `HandleInput`은 `currentState == PAUSED`면 `TryEscNavigateBack()`이 false라서 곧바로 재개시키는 분기를 탄다 (`GameManager.cpp:148`). 반면 `Scene_Paused`는 같은 ESC로 인벤토리만 닫으려 한다. 어느 쪽이 먼저 소비하는지는 호출 순서에 달려 있어 **미확인** (기존 문서 #5와 동일).
- **로비·일시정지는 마우스 전용**이다. 위/아래 키 이동이 없다 (호버 + 클릭만). 반면 증강 선택은 키보드 포커스(`augmentKeyboardFocus`), PLAY 패널은 키보드 이동, 설정은 W/S 목록 이동이 있다. 화면마다 지원 수준이 달라 컨트롤러·키보드 사용자에게 일관성이 없다.
- **클릭 판정이 두 가지**: 대부분 `hov && lmb && !g_LmbPrev`(누른 순간), `UIButton`만 `hover && lmbPrev && !lmb`(뗀 순간).
- 재진입(리셋) 감지 방식이 **세 가지**: 로비는 `g_MainMenuEntryT`, 설정은 `wasInline`+`s_SettingsInlineNeedsReset`, 일시정지는 "마지막 호출 후 0.12초 경과"(`ScenePause.cpp:91`). 마지막 방식은 프레임 지연이 0.12초를 넘으면 열린 확인 대화상자·진입 애니메이션이 초기화될 수 있다 (**미확인**).

## 6. 상태 관리

- 장면 상태 대부분이 **함수 안 `static`** 이다. `Scene_SettingsInline` 한 함수에만 정적 변수가 약 40개(호버 3차원 배열 `optHover[5][10][8]`, 스냅샷, 스크롤, 키 캡처 등), 파일 전체 1,719줄. 장면을 테스트하거나 두 번 열거나 외부에서 초기화하기 어렵다.
- 설정 저장 구조(`SettingsSnapshot` 캡처/복원/비교, dirty 확인 대화상자)는 잘 짜인 부분이다.
- 로비 ↔ 패널 상태 공유는 `extern` 전역(`g_MainMenuEntryT`, `s_MainMenu*Panel`, `g_SettingsEntryT` …)을 통한다 (`SceneInternal.h:10-15`). 이름은 `s_`(파일 정적)인데 `extern`이라 규칙이 흐려진다.

## 7. 다국어(i18n) 방식

한 코드베이스에 **5가지** 혼재: `StrId` 표(`T(StrId)`), `LStr`, 즉석 `const wchar_t* X[3]` 배열, `ShopText`, `LangIndex()==0 ? … :` 삼항. 장면별 문자열 리터럴 수(`L"` 개수): SceneSettings 100, SceneCodexInline 57, SceneCodex 46, SceneAugment 44, SceneRunConfig 40, SceneShop 39, SceneRunEnd 33. 인덱스 함수도 `LangIndex()`, 직접 `(int)g_Language` 캐스팅 등이 섞여 있다. `main.cpp:6406` JP 크리에이티브 HUD 문자열이 `?化`로 깨져 있음 (이전 분석서와 동일).

## 8. HUD (잘 된 부분)

- `VitalsHudModel.h`, `SkillHudModel.h`는 GL 없는 순수 모델로 분리되어 `tests/vitals_hud_model_test.cpp`, `skill_hud_model_test.cpp`가 있다. `WaveHud.h`는 대응 테스트가 없다.
- 다만 HUD 호출 조립(`main.cpp:6540-6660`)과 업적 토스트, 크리에이티브 라벨, 데미지 숫자, 콤보, FPS는 **main()에 직접 인라인**돼 있고 하드코딩 문자열·색·위치를 포함한다 (`main.cpp:6375-6440`, `6606-6652`).

## 10. 개선 제안 (위험 낮은 순)

1. **입력 헬퍼 일원화**: `EdgeTracker`(ESC/RMB/LMB 에지 + `inputFocusChanged` 처리)를 하나 만들어 5곳의 `prevEsc`를 교체. 클릭 판정은 "누른 순간"으로 통일하고 `UIButton`은 호출처 확인 후 정리.
2. **색 토큰 적용**: 장면의 청색 리터럴을 `GetUiTheme().Frame/Accent`로 치환하고 `UiDepth` 단계에 맞춰 알파 정리. 이후 LIGHT 테마 노출 여부 결정.
3. **버튼·뒤로 버튼 통합**: `DrawPanelButton`/`DrawUnifiedMenuCommand` 병합, 뒤로 레일 수치 한 곳으로 (기존 PP-08).
4. **재진입 리셋 규약 하나로**: `Scene::OnEnter()` 같은 명시적 진입 훅, 0.12초 추정 제거.
5. **로비/일시정지 키보드 내비게이션 추가** (위/아래+Enter, 현재 호버 상태 변수 재사용).
6. **번역을 `StrId`/`LStr`로 수렴**, 우선 SceneSettings(100)·Codex(103)부터. 용어집 작성.
7. **main() HUD 조립 분리**: `DrawIngameOverlay()` 함수로 이동만 (동작 변경 없음).
8. 장기: `SceneSettings`를 상태 구조체 + 그리기 함수로 분할.
