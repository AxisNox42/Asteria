# Asteria UI 디자인 양식 (2026-11-02 정리)

출처: `Docs/QA/UI_Text_Audit_Plan.md`, `PlayPanel_Refactor_Plan_2026-10-13.md`, `Wave_HUD_Handoff_2026-10-17.md`, `superpowers/specs/2026-10-17-skill-hud-design.md`, `Render/UiColors.h`, `Render/HudLines.h`, `Scenes/SceneUI.cpp`, 스모크 캡처 `build/smoke/reftest/`. 기존 문서와 코드에서 읽어 낸 규칙이며, 새로 만든 기준이 아니다.

## 1. 핵심 원칙

1. **판·막·카드 없이 선과 글자로만 그린다.** 패널 배경, 뒤판, 둥근 카드를 쓰지 않는다. 선택 상태는 밝기, 세로선, 노드(점·마름모)로만 구분한다. 예외: 증강 카드 선택 화면은 면을 채우지 않은 윤곽선 카드를 쓴다 (`Augment_Card_Draw_Design.md`).
2. **어떤 배경화면에서도 읽혀야 한다.** 게임 창이 투명이라 바탕화면 밝기를 알 수 없다. 배경에 맞춰 색을 바꾸지 않고, 모든 배경에서 통하는 방식(글자 halo, 선 아래 색조 키라인)만 쓴다. 검증은 어두운 배경(실제 크기 캡처)과 밝은 회색 배경(1920×1080 강제 크기) 둘 다 한다.
3. **별자리 언어.** 선·호·점 노드·마름모·틈 있는 링으로 구성한다. 채움은 타이머를 나타내는 12시부터 시계방향 부채꼴 하나뿐(웨이브 노드, 스킬 쿨다운, 정예 칸 공통).
4. **장식은 조용히, 상호작용은 선명하게.** 장면당 주 앰비언트는 하나. 장식 펄스는 Interactive 단계 이상으로 올라가지 않는다 (`UiDepth`).
5. **텍스트는 한 줄·역할 4단계.** 버튼에 보조 줄을 두지 않는다. 상태 정보가 필요하면 버튼 밖 보조 문구로 둔다.

## 2. 타이포그래피

| 단계 (`UiTextLevel`) | 기준 높이 | 용도 |
|---|---|---|
| Title | 46px × 1.0 (버튼 라벨은 40px 해석) | 버튼 라벨, 화면 제목, 설정 값 |
| Subtitle | × 0.82 (36px) | 보조 구획 제목, 토글 문구 |
| Description | × 0.56 (20px) | 본문, 설정명, 값 |
| Supporting | × 0.42 (18px) | 짧은 안내, 키 글자, FPS |

- 전부 `UiTextScale(renderer, level, UiScale(sw, sh))`로 계산. 직접 숫자 스케일을 쓰지 않는다.
- 글꼴은 Chakra(라틴) → Orbit(한글) → Jua → Kosugi(일본어) 폴백. 렌더러 3개(L/S/XL).
- 한/영/일 **최장 문구 폭**으로 버튼 맞춤(`MaxLocalizedTextWidth`)을 계산해 언어를 바꿔도 위치·호버 영역이 변하지 않게 한다.
- 글자 그림자는 은은한 오프셋 하나(`DrawShadowedText`)와 렌더러 halo. 네 방향 키라인은 쓰지 않는다.
- 문구는 KR/EN/JP 3개 국어 한 벌. 영어 제목은 대문자(`PLAY PAUSED`, `CONTINUE`).

## 3. 색

- 기본 청색 계열: Frame `(0.18, 0.62, 0.96)`, Accent `(0.10, 0.68, 1.00)`, 텍스트 `(0.92, 0.96, 1.00)`, 보조 텍스트 `(0.58, 0.70, 0.84)`. 일시정지·확인 대화상자 등은 `(0.48, 0.82, 1.0)`, 뒤로 버튼은 `(0.34, 0.72, 1.0)`.
- 경고·파괴: 따뜻한 주황~붉은색은 **활성화되는 순간에만** 섞는다 (EXIT 호버, 확인 대화상자 YES `(1.0, 0.32, 0.28)`, HP 25% 미만만 빨강).
- 역할색: 정예 주황, 최종 금색, 일반 하늘색, FOCUS 민트, RAIN 주황 등 의미가 있는 색은 고정. 게임플레이/VFX 색은 UI 팔레트와 분리 (`RoleCol`).
- 깊이 단계 알파 (`UiDepth`): Ambient 0.055 · Structural 0.14 · Interactive 0.58 · Focus 0.94 · Disabled 0.38 · Hidden 0.14. 잠긴 항목은 구조만 보이게(알파 0.14~0.42).
- 키라인: 선 글리프마다 자기 색 × 0.18, 알파 0.88, 두께 +3.2·hs 를 먼저 깔고 본 선을 위에 그린다 (`hud_lines::KeyCol`).

## 4. 레이아웃

- 기준 해상도 1640×910, `UiScale = clamp(min(sw·0.94/1640, sh·0.90/910), 0.70, 1.35)`. 모든 크기·간격에 곱한다.
- **왼쪽 정렬 명령 레일.** 로비·일시정지는 왼쪽(`max(58·s, sw·0.075)`)에 세로 버튼 줄, 그 왼쪽 36px에 앵커 세로선(1.2px, 알파 0.17)과 위·아래 끝 마름모.
- **하단 좌측 뒤로 버튼**: 모든 하위 페이지 공통, 286×64·s, `BottomLeftActionX/Y`.
- 하위 페이지는 3열(목록 / 별자리 / 상세) 또는 좌우 같은 너비 열 + 중앙 열이 화면 중앙. 좌우 대칭을 기본으로 한다.
- 1280×720, 1920×1080, 2560×1440(+2560×1600, 2560×1080)에서 겹침·잘림이 없어야 한다.
- 입력 영역(호버·클릭)은 보이는 글자·버튼 위치와 일치하고 이웃 행과 겹치지 않는다(히트 패딩 4px 내외, 과거 26px는 이웃 오클릭 원인).

## 5. 상호작용·모션

- 호버 값은 지수 보간(`UpdateMenuCommandHover`, 속도 10/s)으로 0~1. 선택·호버 시 **슬라이드 바 한 쌍**이 버튼 양옆(또는 왼쪽만)에서 바깥으로 이동하고 끝에 마름모. 아래에서 스캔 라인이 천천히 훑는다.
- 호버 중 버튼은 왼쪽으로 10px 이동. 비선택 행은 알파를 낮추되 하한을 둔다.
- 선택 시 나머지 행은 아래로 28px 밀리며 흐려지고, 선택 행은 18Hz 펄스 후 장면 전환(0.4s, quintic ease `SceneTransitionEase`).
- 진입: 제목 → 버튼이 0.14s 간격으로 오른쪽에서 34px 슬라이드 인 → 보조 텍스트. 클릭하면 인트로 건너뛰기.
- 파괴적 명령(EXIT, ABANDON, RESTART)은 중앙 확인 대화상자(YES 경고색 / NO 청색)를 거친다.
- 호출된 클릭이 대화상자를 즉시 응답하지 않게 0.12s 지연.

## 6. 전투 HUD 규칙

- 선 글리프만: 웨이브 트랙(○ 일반 / ◇ 정예 / ◈ 최종, 7칸 창, 양 끝 40% 흐림), 스킬 HUD(키 SHIFT/Q/E/R 원, 쿨다운 부채꼴, 패시브 세모), HP 호(240°, 10% 눈금), XP 하단 선.
- 글자는 키 이름과 남은 초만. 스킬 이름·디버프 줄·몹 그림 같은 설명은 HUD에 넣지 않는다.
- 현재 상태는 알파 0.85 자기 색 채움, 위험은 숫자 색만 바꾼다(칸 색 고정).
- Model(GL 없음, 테스트) / View(그리기) 분리.

## 7. 체크리스트 (새 UI를 만들 때)

- [ ] 판·카드 없이 선·글자·노드만 썼는가
- [ ] 텍스트가 4단계 중 하나이며 `UiTextScale`로 계산했는가
- [ ] 세 언어 최장 문구에서 잘림·겹침이 없는가
- [ ] 선 글리프 아래 키라인이 있는가, 어두운/밝은 배경 둘 다 읽히는가
- [ ] 색을 리터럴로 새로 만들지 않고 기존 청색 계열/역할색을 썼는가
- [ ] `UiScale`을 모든 크기·간격에 곱했는가
- [ ] 호버·클릭 영역이 보이는 위치와 일치하는가
- [ ] 파괴적 동작에 확인 대화상자가 있는가
- [ ] ESC·우클릭으로 뒤로 가는가 (`EscPressedEdge`), 키보드 이동이 되는가 (`MenuKeyboardNav`)
- [ ] 스모크 캡처(실제 크기 + 비율이 다른 크기)로 확인했는가
