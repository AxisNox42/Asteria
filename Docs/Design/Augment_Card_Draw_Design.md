# 증강 선택 — 카드 드로우 기획 (2026-11-03)

현재 증강 선택(`Scene_AugSelectConstellationPolished`, `SceneAugment.cpp`)은 후보 3개를 하나의 궤도 위 별자리로 띄우고 오른쪽 상세 패널에 설명을 보여 준다. 이를 **레벨업마다 카드 5장을 뽑는 연출**로 바꾼다. 설명이 카드 안으로 들어가므로 별도 상세 패널은 없앤다.

시각 시안: Artifact "Asteria Augment Cards" (인터랙티브 목업, 드로우·플립·호버·선택 재생).

> **변경 (2026-11-03):** 웨이브 클리어 증강 카드는 **3장**으로 줄였다 (`GameManager::kAugChoiceMax` = 3). 레벨업 능력치 카드도 3장이다. 3장 이하일 때는 카드를 1.18배 키운다 (`aug_card::kFewBoost`). 아래의 5장 기준 레이아웃·연출 설명은 카드 수만 다를 뿐 그대로 적용된다 (레이아웃 모델은 최대 5장까지 그대로 지원).

## 1. 목표

- 레벨업 순간을 "덱에서 운명을 뽑는다"는 손맛 있는 이벤트로 만든다.
- 후보를 3개에서 **5개로 늘리고**, 다섯 후보를 **한눈에 비교**한다. 지금은 호버해야 설명이 보이는데, 카드는 다섯 설명을 동시에 보여 준다.
- 별자리 언어(선·노드·마름모)를 유지한다. 카드도 선으로만 그린다.

## 2. 디자인 원칙과의 관계

`Asteria_UI_Design_Guide.md` §1-1은 "판·막·카드 없이"를 규칙으로 둔다. 이번 카드는 이 규칙의 **예외로 명시**하되, 정신은 지킨다.

| 규칙 | 카드에서 지키는 방식 |
|---|---|
| 판·막 금지 | 카드는 **채운 면이 없다.** 윤곽선(모서리 깎은 직사각형) + 키라인만. 뒤의 전투 화면이 비친다 |
| 채움 금지 (선만) | 배경 별자리도 선·노드만. 면 채움 없음 |
| 점선 금지 | 뒷면 문양, 흐린 상태 모두 실선 + 알파로만 |
| 가독성은 글자 단위 | 글자 halo + `DrawShadowedText`. 별자리는 글자 줄과 겹치는 구간에서 알파를 더 낮춘다(§4.3) |

> 결정 (2026-11-03): 별자리는 **반투명**. 카드 면은 채우지 않고 별자리 선만 반투명하게 그린다(§4).

## 3. 카드 구성

```
 ◆─────────────────────────◆   ← 모서리 마름모 (깎인 모서리)
 │  ·  ·  ◇ ◇ ◇  ·  ·     │   ← 등급 노드 (1~5개, 등급색)
 │                         │
 │       화 염 탄          │   ← 제목 (Subtitle, 가운데)
 │  ───────◆───────        │   ← 구분선 + 중앙 노드
 │                         │
 │  액티브 · 9초           │   ← 설명 1줄째: 종류/쿨다운 (보조색)
 │  착탄 시 폭발하는        │
 │  화염탄 발사 (직격 공격  │   ← 설명 본문 (Description)
 │  력 500% + 폭발 반경    │
 │  공격력 300%)           │
 │       ╲  ·─·            │   ← 배경 별자리 (계열별, 흐림)
 │        ·    ╲·          │
 │            [1]          │   ← 단축키 (Supporting)
 ◆─────────────────────────◆
```

- **최상단 = 제목**만. 제목이 넓으면 기존처럼 0.04씩 줄여 폭에 맞춘다(하한 0.55).
- **그 외는 전부 설명 텍스트.** 등급·종류·쿨다운도 별도 배지가 아니라 설명의 첫 줄(보조 텍스트색)로 둔다.
- 등급은 글자가 아니라 **프레임 색 + 상단 등급 노드 개수**(일반 1 · 희귀 2 · 에픽 3 · 전설 4 · 신화 5)로 보여 준다. 색약 대비도 된다.
- 단축키 `[1]`~`[5]`는 카드 하단 중앙.

### 3.1 크기 (기준 1640×910, 모두 `UiScale` 곱)

| 항목 | 값 |
|---|---|
| 카드 | 280 × 410 |
| 카드 간격 | 24 |
| 모서리 깎기 | 18 |
| 안쪽 여백 | 좌우 28, 상 34, 하 30 |
| 프레임 선 | 1.4px (호버 2.2px) + 키라인 |
| 제목 | `UiTextLevel::Subtitle` |
| 설명 | `UiTextLevel::Description`, 최대 8줄 |
| 등급 노드 | 마름모 반경 4, 간격 14 |

5장 폭 1496 (기준 1640 안). 1280×720 (UiScale 0.70) → 카드 196×287, 5장 폭 1047 — 들어간다. 2560×1080처럼 낮고 넓은 화면은 높이 기준(sh·0.90/910)으로 줄어든다.

설명 8줄 초과 시: 줄 수를 줄이지 말고 설명 텍스트 스케일만 0.04씩 줄여 맞춘다(하한 Supporting). 세 언어 최장 문구로 검증한다.

## 4. 배경 별자리 (계열별 20종)

증강 enum 접두어가 이미 계열을 나눈다 (`P_FLAME_…`, `A_FLAME_…`). 계열마다 고유 별자리 하나를 카드 뒤에 깐다. 같은 계열의 패시브·액티브는 같은 별자리 → 시너지 계열이 눈에 들어온다.

| 계열 | 별자리 모티프 | 계열 | 별자리 모티프 |
|---|---|---|---|
| NIGHT 밤 | 초승달 호 + 별 3 | HERESY 이단 | 후광 원 + 엇갈린 십자 |
| CHRONO 시간 | 원 위 4노드 + 바늘 두 선 | HUNTER 사냥 | 화살촉 + 조준 원 |
| GALE 질풍 | 흐르는 S 지그재그 | PERFORM 공연 | 후프 원 + 리본 꼬리 |
| SHADOW 그림자 | 어긋나 겹친 삼각형 둘 | STILL 정적 | 수평선 위 삼각형 |
| STONE 바위 | 육각 결정 | VEIN 광맥 | 갈라지는 가지 선 |
| FLAME 화염 | 위로 솟는 세 갈래 | NOVA 신성 | 중심 + 8방사 |
| GEM 보석 | 팔각 컷 + 내부 선 | LUCK 행운 | 네 잎 루프 |
| STORM 폭풍 | 번개 지그재그 | LIFE 생명 | 뻗는 나무 가지 |
| ABYSS 심연 | 안으로 감기는 나선 | SPARK 전기 | 짧은 방사 스파크 |
| FLIGHT 비행 | 날개 V | EDGE 칼날 | 긴 검선 + 가드 |

규칙:
1. 선·노드만. 다각형 모서리는 날카롭게 유지, 가시(thorn) 장식 없음.
2. **반투명**: 기본 알파 0.30, 호버 시 0.46, 색은 등급색. Structural(0.14)보다 진하지만 Interactive(0.58) 아래로 둬서 글자·프레임보다 앞에 나서지 않게 한다. (계열은 모양으로, 등급은 색으로 구분 — 20색 팔레트는 만들지 않는다.)
3. **글자 줄 영역(제목·설명 박스)과 겹치는 선은 알파 × 0.45.** 막을 까는 대신 별자리 쪽을 비켜 준다.
4. 카드 높이의 아래 55% 영역에 무게중심. 위쪽은 제목이 차지.
5. 노드는 천천히 깜빡임(주기 2.4~3.6s, 카드마다 위상 다름). 장식 펄스는 Interactive 알파를 넘지 않는다.

데이터: `AugFamily` enum + 계열별 `{정점(카드 정규 좌표 0~1), 간선}` 테이블. `AugDef`에 `family` 필드를 추가하거나, enum 범위 대신 명시 테이블로 매핑한다(정렬이 바뀌어도 안전하도록 명시 테이블 권장).

## 5. 드로우 연출 (레벨업 1회 = 5장)

전체 약 2.1s (전설·신화가 있으면 +0.2s씩). 어떤 클릭이든 즉시 끝 상태로 건너뛴다(가이드 §5 인트로 스킵).

| 시각 | 단계 | 내용 |
|---|---|---|
| 0.00 | 덱 등장 | 화면 하단 중앙에 뒷면 카드 윤곽 4장이 2px씩 어긋나 쌓인 덱이 페이드 인(0.18s) |
| 0.20 | 드로우 | 0.09s 간격으로 5장이 덱에서 뽑혀 호를 그리며 제자리로 이동(0.42s, quintic ease). 이동 중 -8°→0° 회전 |
| 0.98 | 대기 | 마지막 장이 자리 잡음. 뒷면 상태로 잠깐 정렬. 뒷면 = ASTERIA 문양(틈 있는 링 + 8방 노드), 등급색이 미세하게 새어 나옴 |
| 1.02 | 뒤집기 | 왼→오 0.08s 간격으로 플립(가로 스케일 1→0→1, 0.24s). 0 지점에서 앞면으로 교체 |
| 1.26~ | 별자리 그리기 | 각 카드 앞면이 보이면 계열 별자리 간선이 노드→노드로 그어진다(0.35s) |
| 1.31~ | 글자 | 제목 페이드 인 → 설명 줄 단위 0.03s 간격 페이드 인 |
| 약 1.9 | 입력 가능 | 호버·키 입력 활성 |

### 5.1 등급 연출

- **전설/신화**는 플립 직전 0.20s 더 멈추고, 뒷면 링이 등급색으로 차오른 뒤 뒤집힌다. 뒤집힐 때 짧은 선 파편 8개가 방사(0.4s).
- 같은 드로우에 전설 이상이 있으면 그 카드를 **마지막에** 뒤집는다(나머지는 왼→오 순서 유지).
- 일반/희귀/에픽은 추가 연출 없음 (장식은 조용히).

### 5.2 상호작용

- **호버**: 카드 위로 14px 상승, 프레임 2.2px·Focus 알파, 별자리 알파 0.30, 슬라이드 바 한 쌍이 카드 아래 양옆으로 이동 + 끝 마름모. 나머지 카드는 알파 0.55(하한).
- **키보드**: 기존 선택 화면과 같은 방식 — 1~5 로 카드에 포커스, Space 로 확정. 클릭은 바로 확정. 포인터가 카드 밖으로 나가도 마지막 포커스를 유지한다(호버 후 Space).
- **선택**: 선택 카드가 18Hz 펄스(0.15s) → 별자리 선이 바깥으로 풀리며 노드들이 화면 하단 중앙(스킬 줄 위치)으로 0.02s 간격으로 날아가 흡수(0.45s), 도착 지점에 링이 퍼지고 약한 화면 플래시. 나머지 네 장은 **별들의 양분으로 해체**된다(§5.4). 덱으로 돌아가지 않는다.
- 호버·클릭 영역 = 카드 윤곽 그대로(히트 패딩 4px).

### 5.3 레벨업이 쌓였을 때

덱 옆에 남은 드로우 수를 마름모 노드로 표시(◆◆ = 2회 남음). 선택 후 덱이 그대로 있다가 바로 다음 5장을 뽑는다(덱 등장 단계 생략, 0.2s부터).

5장이 되며 연출이 약 2.1s로 길어졌다. 레벨업이 연달아 쌓이면 두 번째부터는 플립 간격을 0.04s로 줄이는 안을 검토한다(클릭 스킵은 그대로).

### 5.4 고르지 않은 카드 — 별들의 양분으로 해체

세계관(프로그램된 우주, 별자리 = 코드로 돌아가는 기계)에 맞춰, 버려진 카드는 사라지지 않고 우주의 별로 흡수된다. **연출만** 있고 게임 수치(별가루·확률 등)에는 영향이 없다.

| 시각 (선택 기준) | 내용 |
|---|---|
| 0.03~0.18 | 글자(제목·설명·등급 마름모)가 먼저 페이드 아웃 |
| 0.05~ | 윤곽선이 약 34px 길이 조각으로 끊긴다. 조각마다 시작 시각 = 0.05 + 0.06 × (고른 카드와의 칸 거리) + 0~0.12 무작위 → **고른 카드에서 바깥으로 퍼지는 파도** |
| 조각 0.55s | 카드 중심 바깥쪽 + 위쪽으로 흩어지며 회전, 길이 60%까지 줄고, 색이 등급색 → 흰빛으로 바뀌며 사라진다 |
| 0.12~ | 별자리 선이 페이드 아웃(0.12s)되며 노드가 하나씩(0.015s 간격) 떨어져 위로 떠오른다(0.75s) |
| 도착 | 노드가 별이 된다: 반경 1.1의 등급색 별로 그 자리에 남아 반짝이고, 도착 순간 잠깐 밝게 빛난다(빛 감쇠 약 0.7s) |

- 선·점만 쓴다(채움·점선 없음). 조각은 실선, 노드는 점.
- 전투는 선택 화면 아래에서 멈춰 있어, 긴 종료 꼬리는 슬로우모션처럼 보였다. 그래서 종료는 0.95s로 짧게: 노드는 떠오르며 흰빛이 되어 꺼지고(0.45s, 남아서 반짝이지 않음), 딤은 0.10~0.95s에 부드럽게(smoothstep) 걷히며 그 끝이 곧 화면의 끝이다. 하단 스킬 HUD는 딤이 걷히는 만큼 다시 나타난다. 딤은 열릴 때도 0.35s에 걸쳐 들어온다. 이 화면의 딤은 카드 장면 하나만 그린다(예전 GameManager 고정 0.45 막은 상태 전환 때 툭 켜지고 꺼져서 뺐다). 다음 보상이 이어지면 딤은 걷지 않는다.
- 다음 드로우는 기존대로 선택 0.95s 뒤에 시작하고, 떠오르는 노드는 그 위로 계속 흘러간다.

## 6. 구현 메모

- **후보 수 3→5**: `GameManager.h` 의 `augChoices[3]` → `[5]`, `GameManager.cpp` 194·273행 초기화 루프와 후보 생성 루프, `SceneAugment.cpp` 의 `std::min(3, augChoiceCount)` 상한. 풀이 부족하면(유일 증강 소진 등) 남은 수만큼만 뽑는다. `GameManager.h` 구조체 레이아웃이 바뀌므로 crash-triage 체크리스트대로 전체 재빌드한다.
- `Scene_AugSelectCards`(SceneAugment.cpp)로 교체, `Scene_AugSelect`가 호출. 기존 궤도 화면 코드는 지웠다(git 기록에 있음).
- 레이아웃·타이밍·해체 시각·계열 별자리는 `Render/AugCardModel.h`(GL 없음), 테스트는 `scripts/test_aug_card_model.ps1`. 선택 종료 시간 `AUG_EXIT_DUR` 도 `aug_card::kExitDur`(0.95s) 하나로 맞춘다.
- **Model/View 분리**: `AugCardModel`(GL 없음) — 레이아웃 사각형, 단계 타이밍, 플립 순서(전설 마지막), 히트 테스트. 테스트에서 1280×720 / 1920×1080 / 2560×1080 레이아웃 겹침 검사.
- 플립은 카드 중심 기준 가로 스케일. 글자는 스케일 0.15 미만에서 그리지 않는다(뭉개짐 방지).
- `TarotWrap`을 카드 내부 폭으로 재사용.
- 튜토리얼 미니 카드 화면도 같은 씬을 쓰므로(`SceneAugment.cpp:967` 주석) 작은 창에서 스모크 캡처로 확인.
- 검증: 어두운 배경 + 밝은 회색 배경 캡처, 세 언어 최장 설명.

## 7. 결정 사항 (2026-11-03)

1. 별자리는 **반투명** (알파 0.30 / 호버 0.46). 카드 면은 채우지 않는다.
2. **리롤·봉인 같은 카드 조작은 넣지 않는다.** 뽑힌 5장 중 하나를 고르는 것이 전부다.
3. 고르지 않은 카드는 **별들의 양분으로 해체**된다(§5.4). 연출만 있고 수치 영향은 없다.
